# Locale fallback: the chain a locale's data is looked up along

Backs `hc-i18n`'s `Locale::parent` and `Locale::fallback`, and through them
every lookup of a locale's names, templates, numbering system, zone names
and territory names; and the two lookups that do not take that chain, the
day period rules and the plural rules.

## What it is

A locale's data in CLDR is split over files: `en.xml` for English, and
`en_001.xml`, `en_GB.xml` for what English outside the United States and in
Britain write differently. UTS #35 Part 1, "Inheritance and Validity"
[uts35-v48], resolves a value at a path by looking in the locale's own file
and then its parents', to root. The parent of a locale is its identifier
truncated from the right, a subtag at a time ("Truncation"), except where
`supplementalData.xml`'s `parentLocales` name another ("Parent Locales"
[cldr48-supplemental]): `en_GB`'s parent is `en_001`, not `en`, and
`zh_Hant`'s is root, not `zh`, so that Traditional Chinese never takes a
Simplified value.

Two reserved values stop or skip the search. The inheritance marker `↑↑↑`
is read as though the element were absent, and the empty override `∅∅∅`
says that the locale "is to have no value for a path, even if the parent
locale has a value for that path" [uts35-v48].

## How it works

`Locale::parent` takes one step:

1. an extension (`-u-ca-japanese`) is dropped first, since it is a request
   and not an identity; then a variant;
2. where `parentLocales` name the tag, their parent;
3. else the region is dropped, then the script;
4. a bare language's parent is root, `und`, except where `parentLocales`
   name it (`ht` → `fr-HT`, `nb` and `nn` → `no`).

`Locale::fallback` walks the steps from the tag, after replacing a legacy
language subtag by the language CLDR's `languageAlias` gives it (`iw` is `he`,
`tl-PH` is `fil-PH`; `hc_locale_chain` writes that step as `language-alias`)
and after giving a Chinese,
Punjabi or Cantonese tag with no script the script CLDR 48's likely
subtags give it, because those languages' entries are per script.

**Worked examples.**

- `zh-TW`: the likely script makes it `zh-Hant-TW`; that is not in
  `parentLocales`, so the region goes, `zh-Hant`; `parentLocales` send
  `zh-Hant` to root. The chain is `zh-Hant-TW`, `zh-Hant`, `und`.
- `en-AU`: `parentLocales` send it to `en-001`, which truncates to `en`:
  `en-AU`, `en-001`, `en`, `und`. `en-AU` has no entry of its own, so its
  months are `en-001`'s, *Sept* for September.
- `ht`: a bare language that `parentLocales` name, so `ht`, `fr-HT`, `fr`,
  `und`: Haitian Creole takes French names.

A lookup takes the first entry in the chain that states the field asked
for, so an entry states only what differs from its parent. A zone name a
file writes as the empty override stops the search with no name
([zone-names.md](zone-names.md)).

Two kinds of data are keyed by language, not by locale. CLDR's plural
rules name languages, and a few tags (`pt_PT`); `PluralRules::for_locale`
walks the chain, trying the hyphenated rows against each step and then
the step's language ([plural-rules.md](plural-rules.md)). The day period
rule sets of `dayPeriods.xml` name languages too,
and a few tags by script or region (`hi_Latn`, `es_CO`); a locale's rule
set is found by truncating its tag, `zh-Hant-HK`, `zh-Hant`, `zh`, which
the chain would not reach.

A locale's default numbering system is the first tag in the chain that
has one: a carried entry's own, or a regional file's that CLDR gives
another system than the entry it falls back to. `ar.xml` inherits root's
`latn`; `ar_SA.xml` writes `arab`, so `ar-SA`, which has no entry, writes
Arabic-Indic digits while its names are `ar`'s.

## What is carried

- CLDR 48's `parentLocales`, the default component, whole
  (`data::PARENT_LOCALES`, generated by `scripts/locales-cldr.py`,
  `--check`), and the likely scripts of the languages carried per script.
- The default numbering system of every carried entry and of every
  regional file of a carried language whose system is not its entry's
  (`data::DEFAULT_NUMBERING`, the same script): the regional files are
  those `supplementalData.xml`'s `territoryInfo` lists the language for.
- What a locale calls a calendar (`names::calendar_display_name`), which
  the chain looks up entry by entry, each entry asking three tables in
  turn: CLDR 48's calendar names, for the calendars CLDR has a key for
  [cldr48-calendar-names]; the hand-written names of `calendar_names`,
  from a page read in the language; and the title of the locale's own
  Wikipedia article on the calendar (`data::WIKIPEDIA_CALENDAR_NAMES`,
  generated by `scripts/calendar-names-wikipedia.py` from the
  interlanguage links of the article about each calendar
  [wikipedia-calendar-names], the Chinese edition's title in its `zh-hans`
  and `zh-hant` variants for the two scripts). An entry that names the
  calendar in none of them lets the chain go on, so `ja-JP` takes `ja`'s
  ビルマ暦 for `burmese` and `zh-HK` takes `zh-Hant`'s 緬曆; a calendar no
  entry of the chain names has no name, and a page shows its English name
  with no locale-used tag, as `docs/i18n.md`, "What a locale calls a
  calendar", says, with the calendars no article names and why.
- Not yet carried: the `nonlikelyScript` rule of `parentLocales` beyond
  the tags it lists, and the other regional files' names, which a tag
  without an entry takes from its parent.

## Code

- `crates/hc-i18n/src/locale.rs`: `Locale::parent`, `Locale::fallback`,
  `Locale::with_likely_script`.
- `crates/hc-i18n/src/data/cldr48_locales.rs`, generated:
  `PARENT_LOCALES`, `DEFAULT_NUMBERING`.
- `crates/hc-i18n/src/calendar_names.rs`: `sourced_calendar_name`, the
  hand-written names and the lookup of the generated
  `crates/hc-i18n/src/data/wikipedia_calendar_names.rs`
  (`WIKIPEDIA_CALENDAR_NAMES`), which `LocaleData::calendar_name` asks
  after CLDR's names.
- `crates/hc-i18n/src/numbering.rs`: `NumberingSystem::for_locale`.
- `crates/hc-i18n/src/day_periods.rs` and `crates/hc-i18n/src/plural.rs`:
  the lookups by language.
- `Locale::parent_step` and `ParentRule` (`locale.rs`) name the rule of each
  step. The boundary's `hc_locale_chain` writes the chain with that rule,
  `hc_locale_info` what a locale is (parent, default numbering, `minDays`,
  direction, casing, plural rules), `hc_plural_category` the cardinal or
  ordinal category of a number written as text (the operands `c` and `e`
  are not carried), `hc_names`, `hc_case` and `hc_isolate` the names,
  casing and bidi isolates, and `hc_locales` the parent, numbering and
  direction of every carried locale
  (`crates/hyper-calendar/src/i18n_lines.rs`; tests
  `a_locale_resolves_along_its_chain`, `a_locale_describes_itself`,
  `a_number_has_a_plural_category`). CLDR's weekend days are not carried: the
  library reads `weekData`'s `firstDay` and `minDays` only, and the weekend
  laws of the holiday tables are in `hc_holiday_tables`.
